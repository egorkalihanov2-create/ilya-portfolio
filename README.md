# Ilya — Creative Copywriter

Адаптивное портфолио по макету Figma. Проект собран на React, TypeScript, Vite, Tailwind CSS и Motion. Шрифты и все изображения хранятся локально в репозитории.

## Локальный запуск

```bash
npm install
npm run dev
```

Сайт откроется на `http://127.0.0.1:5173/`, редактор кейсов — на `http://127.0.0.1:5173/admin`.

## Редактор кейсов

В редакторе можно менять название, тег и обложку кейса, а также собирать содержимое из произвольного количества текстовых блоков, отдельных изображений или видео и фотокаруселей. Блоки и фотографии внутри карусели можно переставлять.

- структура хранится в `public/content/cases.json`;
- новые файлы загружаются в `public/uploads/`;
- при замене обложки автоматически создаётся облегчённая WebP-версия шириной до 1280 px;
- до нажатия «Сохранить изменения» всё остаётся черновиком текущей вкладки;
- после сохранения открытая публичная страница получает свежий каталог автоматически.

### Передача правок разработчику через GitHub

На сервере можно включить кнопку «Передать в GitHub». Она сохраняет каталог и используемые файлы из `uploads` одним commit в отдельную ветку и создаёт или обновляет Pull Request в `main`. Токен GitHub используется только сервером и никогда не отправляется в браузер.

Создайте fine-grained GitHub token с доступом только к этому репозиторию:

- `Contents: Read and write`;
- `Pull requests: Read and write`;
- `Metadata: Read`.

Затем задайте серверные переменные:

```text
GITHUB_TOKEN=github_pat_...
GITHUB_OWNER=имя-владельца
GITHUB_REPO=ilya-portfolio
GITHUB_BASE_BRANCH=main
GITHUB_CONTENT_BRANCH=admin/customer-content
```

Рабочий процесс:

1. Заказчик меняет кейсы и сохраняет их на сайте.
2. Кнопка «Передать в GitHub» создаёт или обновляет Pull Request.
3. Разработчик проверяет и сливает Pull Request.
4. Railway получает новый `main` и разворачивает утверждённую версию.

Для локальной разработки пароль не нужен: запись разрешена только через localhost. Для размещения админки нужен Node-хостинг с постоянным диском:

```powershell
npm run build
$env:LOCAL_ADMIN="1" # только для приватного локального запуска
npm start
```

На публичном сервере задайте `ADMIN_PASSWORD` длиной от 16 символов, `SITE_ORIGIN` и постоянный `CONTENT_DIR`; пример находится в `.env.example`. GitHub Pages по-прежнему подходит для статической публичной версии, но не может сохранять изменения и загруженные файлы из админки.

### Railway

Подключите репозиторий как Service и создайте Volume с mount path `/data`. Volume хранит сохранённые на сайте изменения до и после их передачи в GitHub. В Variables задайте:

```text
HOST=0.0.0.0
CONTENT_DIR=/data
SITE_ORIGIN=https://ваш-домен
ADMIN_PASSWORD=уникальный-пароль-длиной-от-16-символов
```

Railway автоматически передаёт `PORT`, поэтому задавать его вручную не нужно. Build command — `npm ci && npm run build`, Start command — `npm start`. Автодеплой следует включить только для ветки `main`, чтобы публикация заказчика не разворачивалась до проверки Pull Request.

Если редактор используется локально вместе с текущим GitHub Pages workflow, после сохранения добавьте в Git `public/content/cases.json` и новые файлы из `public/uploads/`, затем сделайте обычный push. Так статическая сборка получит отредактированный каталог и медиа.

```bash
npm run lint

```

## GitHub Pages

Workflow `.github/workflows/deploy.yml` автоматически собирает и публикует сайт после push в ветку `main`. В настройках репозитория GitHub Pages источником должен быть выбран **GitHub Actions**.
